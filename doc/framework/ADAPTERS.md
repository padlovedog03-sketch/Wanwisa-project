**ข้อจำกัดของผู้ประสานงาน (จาร์วิส) ที่ประกาศไว้** — `doc/specs/SPEC-jarvis-coordinator.md` · ด่านดักการลืม
ไม่ใช่การจงใจเขียนเท็จ (scope-discipline ข้อ 5)

- **JC-L1** — The `Tier:` line in Jarvis's first reply is self-reported; nothing reads Jarvis's replies.
- **JC-L2** — After the tier, the §5 route order is checked only at the engineer spawn (Approved spec) and the QA spawn (independent PASS review); every other step, and ending the turn at tier-2 gates, is self-reported.
- **JC-L3** — In a brief, only the presence of a filled `Tier:` and `Files:` line is checked, never truth; `Verify with:`, the threat-model sentence for reviewer and QA, and the `REWORK:` prefix are self-reported.
- **JC-L4** — The R5 split (what Jarvis decides, what goes to the owner) is self-reported; a ruling Jarvis made that was the owner's shows only in the end-of-task report.
- **JC-L5** — Staying silent until the task ends (R7) is self-reported; it is measured afterwards by M1 (Increment 2), not prevented.
- **JC-L6** — Recording a lesson after an owner correction (R8) is self-reported; `memory_lint.py` checks the format and `correction_rate.py` counts lessons with no mechanism, but nothing checks that a correction produced a lesson.
- **JC-L7** — `coordinator_lint.py --approve-ready` runs only when Jarvis runs it before handing the owner an `approve.sh` command.
- **JC-L8** — Jarvis is the default through the committed `agent` setting; a typed `--agent`, or a local or user `agent` setting, replaces it (measured on CLI 2.1.304). When the replacement is "no agent", the UserPromptSubmit hook injects the Jarvis pointer; when it names another agent, nothing does (by design, PRD A3). Remote-control sessions are unproven. Re-probe on a major CLI upgrade.
- **JC-L9** — The Jarvis definition still appears in the subagent list (measured); the spawn guard refuses to dispatch it.

## รายการที่มนุษย์ตัดสินเสมอ — จุดบังคับต่อตัวเชื่อม

รายการ AH1–AH5 และตัวจับคู่ทั้งหมดอยู่ใน `scripts/autonomy.py` (ชั้นแก่น) ตัวเชื่อมแค่ตัดสินว่าจะ*หยุด*ตรงไหน
(SPEC-delegated-autonomy B-AC9, DESIGN §B.4) กฎ "คำสั่งของเจ้าของ" ใช้กับทุกโปรเจกต์ ส่วนที่เหลือใช้เฉพาะ
ตอนที่ autonomy ทำงานอยู่ (ADR-6)

| จุดบังคับ | ก — Claude Code (มี C1) | ข — ผู้ช่วยใดก็ได้ + git (ไม่มี C1) |
|---|---|---|
| คำสั่ง (commands) | **บังคับ** — `guard_bash.py` ปฏิเสธก่อนรัน: คำสั่งของเจ้าของ (`approve.sh` และตัวห่อของเจ้าของ) กับการเขียนทะเบียนผ่าน shell ทุกโปรเจกต์ · คำสั่งตามรายการ AH ตอน autonomy ทำงาน | **หยุดไม่ได้** — จับผลได้ตอนคอมมิต (เส้นทางที่ป้องกัน) และที่ CI เท่านั้น การส่งออกนอก การ deploy และการใช้เงิน จับไม่ได้เลย |
| เส้นทางที่ป้องกัน (paths) | **บังคับ** — `guard_autonomy_paths.py` (Write/Edit/MultiEdit/NotebookEdit) และกฎ redirect/tee/sed -i/cp/mv/rm ใน `guard_bash.py` เพิ่ม `.claude/hooks/**`, `.claude/settings.json`, `.claude/settings.local.json` เอง | **อ่อนกว่า** — `.githooks/commit-msg` → `autonomy.py check-commit`: เส้นทางที่ป้องกันต้องมี trailer `Owner-Approved: <key>` ที่อยู่ในทะเบียน (อยู่ที่ commit-msg ไม่ใช่ pre-commit เพราะ pre-commit มองไม่เห็นข้อความของคอมมิตนี้) · `--no-verify` ข้ามได้ เหลือ CI |
| การเรียกผู้ช่วย (spawn) | ยังเป็นด่านเดิมของ `guard_agent_spawn.py` (อ่านสถานะ) — ตัวตรวจร่วมมาใน increment A | ไม่มีตอนรัน — CI เท่านั้น (increment A) |
| คำสั่งที่เจ้าของพิมพ์เองด้วย `!` | **ยังไม่ได้พิสูจน์** (B-AC5) ว่า hook ก่อนใช้เครื่องมือไม่ทำงานกับคำสั่ง `!` ของเจ้าของ ถ้าทำงาน กฎคำสั่งของเจ้าของจะกันเจ้าของเองด้วย | ไม่เกี่ยว |

**ข้อจำกัดที่ประกาศไว้ (มติเจ้าของงาน 2026-10-20: ด่านจับความพลาด ไม่ไล่ปิดทุกทาง):** ด่านคำสั่งอ่าน*ข้อความ*ของคำสั่ง
shell จึงสะกดการกระทำเดียวกันแบบอื่นได้เสมอ ทางเหล่านี้ด่านไม่กัน และไม่ไล่ปิดทีละทาง:
- คำสั่งที่ซ่อนในสคริปต์ ใน `bash -c "…"`, `python -c`, heredoc หรือ pipe เข้า shell
- git alias (`git -c alias.x=…`), `git bisect run`, `awk` ที่เรียก `system()`
- ย้อนต้นไม้ไปก่อนเปิดใช้ (`git checkout`/`reset --hard` ไปคอมมิตก่อนหน้า, `git stash -u`) และดึงไฟล์ที่ป้องกันจาก ref อื่น (`git checkout <ref> -- <path>`, `git restore --source`)
- symlink ที่สร้างในคำสั่งเดียวกัน และ `cd $HOME/…`
- ตัวห่อที่ไม่อยู่ในรายการ (`arch`, `caffeinate`, `script`) และ `git push --repo=…`
- ตัวเขียนไฟล์นอกรายการของแบบ (`perl -pi`, `truncate`, `unlink`, `rsync`, `find -delete`, `patch`, `chmod`)

ตัวจับย้อนหลัง: commit-msg (เส้นทางที่ป้องกันต้องมี trailer ของเจ้าของ), การป้องกันสาขาที่ฝั่ง remote และ CI
บรรทัดทะเบียนที่เขียนผ่านทางเหล่านี้ผ่าน `verify_approvals` *ในเครื่อง* ได้ เพราะหน้าตาเหมือนของจริง แต่ CI อ่านทะเบียนจาก secret
`APPROVAL_REGISTRY` ที่เอเจนต์เขียนไม่ได้ เอกสารที่ประทับคีย์ปลอมจึงแดงที่ CI — **เฉพาะโปรเจกต์ที่ตั้งขั้นนั้นไว้** และเจ้าของงาน
ต้องเพิ่มบรรทัดเข้า secret ทีละบรรทัด ห้ามคัดลอกไฟล์ทะเบียนในเครื่องไปทั้งไฟล์ การปลอมจึง*ทิ้งร่องรอย* ไม่ใช่*เป็นไปไม่ได้*
งานอ่านอย่างเดียว (`find -name`, `ruff check`, `--help`, `nl`, `sort`, `bash -n`, `py_compile`) ที่เอ่ยชื่อสคริปต์ของเจ้าของ ผ่านเสมอ

## ประตูตรวจ (verify tiers) — ข้อจำกัดที่ประกาศไว้

ด่านห้ามธง (`scripts/verify_record.py check-banned`) อ่านเฉพาะอาร์กิวเมนต์ของ pytest ที่อยู่ตำแหน่งคำสั่ง
(หลัง `env`, `uv run`, `coverage run`, `python -m`) ตัวรันเทสต์อื่นไม่ถูกเดาธง แต่ถูก*ประกาศชื่อ*ในบรรทัด
`limit:` และโปรเจกต์ห้ามธงของตัวเองได้ใน `VERIFY_EXTRA_BANNED` ข้อนี้เหมือนกันทุกตัวเชื่อม เพราะด่านเป็นสคริปต์ชั้นแก่น

ที่ด่านนี้มองไม่เห็น (ไม่ไล่ปิดทีละทาง ตามมติเจ้าของงาน 2026-10-20):
- ตัวห่ออื่นหน้า pytest (`timeout`, `nice`, `poetry run`, `exec`, `command`, `xargs`) และตัวเลือกของตัวห่อที่รับค่า
  → ในขั้นที่อยู่ใน `VERIFY_TEST_STEPS` มีบรรทัด `limit:` ขั้นอื่นเงียบ
- ตัวแปลภาษาที่ไม่รู้จัก (`pypy3`, `py`) และการเปลี่ยนชื่อ pytest → เหมือนข้อบน
- ธงในตัวแปรหรือ `$(…)` → เงียบ
- อาร์กิวเมนต์ที่พิมพ์ให้ `verify-fast.sh` ตรวจด้วยตารางของ pytest เสมอ → ธงของตัวรันอื่นผ่านเงียบ
- `--flake-runs` → เงียบ แต่ไม่มีผลถ้าไม่มี `--flake-finder` ซึ่งถูกห้ามอยู่แล้ว (ส่วน `--force-flaky`, `--max-runs` ถูกห้ามเสมอ เพราะการรันซ้ำทำให้เทสต์ที่พังกลายเป็นผ่าน และการนับจำนวนจับไม่ได้)
- `eval` และ `bash -c "…"` → มีบรรทัด `limit:`

ตัวจับย้อนหลัง: เมื่อตั้ง `VERIFY_COLLECT_CMD` กับ `VERIFY_TEST_STEPS` แล้ว การกรองหรือหยุดกลางทางทำให้จำนวนที่รันไม่เท่าจำนวนที่เก็บได้ → RED
ยกเว้นการรันซ้ำ ซึ่งจำนวนยังเท่าเดิม
