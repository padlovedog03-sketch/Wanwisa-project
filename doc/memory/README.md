# วิธีเขียนความจำของโปรเจกต์

Status: Living
Upstream: `scripts/memory_lint.py` (ตัวตรวจ) · NORTH-STAR บทบาทที่สอง "รู้จักคุณ"

ความจำคือสิ่งที่ผู้ช่วยต้องรู้ทุกครั้งที่เริ่มงาน โดยที่เจ้าของงานไม่ต้องพูดซ้ำ: มติที่ตัดสินแล้ว ความชอบ
บทเรียนจากความพลาด และที่อยู่ของแหล่งข้อมูลภายนอก **มันอยู่ในคลังโค้ด ไม่ใช่ในโฟลเดอร์ส่วนตัวของเครื่องมือ**
เพราะความจำที่อยู่ในเครื่องมือเดียวบนเครื่องเดียว เครื่องมืออื่นและเพื่อนร่วมทีมมองไม่เห็น

## หนึ่งเรื่อง หนึ่งไฟล์

```markdown
---
name: <slug ตรงกับชื่อไฟล์>
description: <หนึ่งบรรทัด ใช้ตัดสินว่าเกี่ยวกับงานตอนนี้ไหม>
type: user | feedback | project | reference
status: active | superseded
date: YYYY-MM-DD
source: <มาจากไหน — คำพูดเจ้าของงาน คอมมิต หรือเหตุการณ์ ต้องตรวจย้อนได้>
superseded_by: <slug>        # ใส่เมื่อ status เป็น superseded เท่านั้น
---

<ตัวเรื่อง> แล้วตามด้วย **Why:** และ **How to apply:** สำหรับ feedback/project
```

## วงจรชีวิต

1. **รับเข้า** — มีที่มาเสมอ เรื่องที่ไม่มีที่มาตรวจซ้ำไม่ได้ จึงเชื่อไม่ได้
2. **แทนที่ ไม่ใช่ขัดกันเงียบ ๆ** — มติใหม่ล้มมติเก่า: เรื่องเก่าเป็น `superseded` ชี้ไปเรื่องใหม่ แล้วเอาออกจากสารบัญ
3. **ตัดแต่ง** — สารบัญมีเฉพาะเรื่องที่ยังมีผล และยาวไม่เกินงบ (`INDEX_BUDGET`) เพราะสารบัญที่ถูกตัดท้าย
   ซ่อนมติที่ใหม่ที่สุด
4. **ห้ามเก็บสิ่งที่คลังโค้ดบอกอยู่แล้ว** — โครงสร้างโค้ด ประวัติ git และกฎใน `AGENTS.md` ไม่ต้องจำซ้ำ

## ข้อมูลส่วนบุคคล

ความจำขึ้นคลังโค้ด จึงห้ามมีค่าของข้อมูลส่วนบุคคล (เลขบัตร เลขหนังสือเดินทาง ที่อยู่ เบอร์โทร) และห้ามมี
ความลับ อ้างถึงคนด้วยบทบาท ไม่ใช่ชื่อ เว้นแต่เจ้าตัวตกลงแล้ว
